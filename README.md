# ORBIS · 全球运输模拟

一个可以直接在本机运行的中文网页版空海运输经营游戏。地图、设施和公开环境数据真实；运输班次、载具性能、经济和事件概率是游戏模拟。

## 发布到网络

已支持 GitHub Pages：玩家浏览器承担仿真计算并独立保存进度，作者电脑无需持续开机。上传、Pages 开关、定时世界更新和完整命令见 [DEPLOY.md](DEPLOY.md)。

- 构建发布版：node scripts/build-static.mjs
- 校验：node scripts/verify-static.mjs
- 预览：node scripts/preview-static.mjs，打开 http://127.0.0.1:8790/orbis/
- GitHub Actions 计划每 12 小时更新公共世界数据并部署；以来源实际成功时间为准。
- 本机版本仍使用 data/save.json；网络版使用玩家浏览器存档，可导入 / 导出迁移。

## 启动

双击 **start.cmd**，浏览器会打开 http://127.0.0.1:8787 。再次运行不会重复启动同一个服务。

- 双击 **stop.cmd** 停止本项目的后台服务。
- 需要 Node.js 22 或更新版本。启动器会优先寻找系统 Node.js，也会识别这台电脑已有的 Codex Node.js 运行时。
- 无需 npm install；地图库、地图、设施目录已随项目保存。
- 浏览器建议 Edge、Chrome 或 Firefox。
- 备用端口：powershell -ExecutionPolicy Bypass -File .\start.ps1 -Port 8790
- 离线启动：powershell -ExecutionPolicy Bypass -File .\start.ps1 -Offline
- 命令行前台启动：node server.mjs

不要直接双击 public/index.html。数据和存档需要本机 HTTP 服务。

## 怎么玩

1. 点击右上角播放。默认 96×；1× 表示真实 1 秒推进游戏 1 分钟。航空可用 24× / 96×，远洋海运可用 720×，也可以每次推进 6 小时。
2. 右侧支持国家、行政区、城市、设施名，以及 IATA / ICAO / 本地代码 / 港口代码。搜索“丹麦”可展开行政区或城市，再选机场；搜索“北京”列出首都 PEK / ZBAA、大兴 PKX / ZBAD 等设施。点击地图上的设施也可设置起终点。
3. 选择现有载具，或在出发地租入新的载具。现有载具必须通过前序班次抵达起点，不能在地图上瞬移。
4. “推荐路线”对航空生成最短大圆线，对海运在开放航路网络上求最短路。推荐路线不承诺避开所有风险。
5. “在地图上自由绘制”允许添加、拖动和删除途经点。可以经过战争演练区、走不合理的弯路，甚至把船舶路线画上陆地。系统会警告，但不阻止提交。
6. 调整出发燃油，展开“班次衔接与出发时间”设置排程。允许衔接目的地距离起点 150 km 内的前序运输；跨空海转运至少等待 3 小时。
7. 点击班次右侧箭头，查看计划、资源、前后衔接和事件；待出发班次可修改或取消。执行中的正常班次可接管改航，使用当前位置和剩余燃油继续结算。
8. “经营”查看收入、成本、载具位置、维护压力和成长。完成 3 班开放周转、维护与枢纽容量投资。8 班和 15 班为后续成长里程碑；实际系统复杂度随载具、班次、联运关系和枢纽共享增加。

初始提供 7 部载具、9 个模拟班次。所有起终点都来自真实设施目录，并不声称这些班次是现实世界正在执行的航班或船期。

## 分区检索和设施类型

- 点击起点或终点输入框，从“全球 → 大洲 → 国家 / 地区 → 行政区 → 城市 → 设施”逐级选择。国家下可切换“按行政区 / 按城市”，顶部路径可返回任一级。
- 可直接输入“丹麦”“北京”“哥本哈根”，或输入 PEK、ZBAA、CPH、EKCH 等代码；精确代码优先。保留原名和多语言城市别名，部分小城与行政区仍使用来源原文。
- 搜索结果显示总数；“加载更多设施”和“展开更多行政区 / 城市”可继续查看，不再只提供前 18 条。
- 类型筛选支持陆地机场、直升机起降点和水上机场。选择起降点后会匹配直升机，选择水上机场后会匹配两栖水上飞机。已有载具或在途任务仍需保持设施类型兼容。
- 勾选“含停用记录”可查阅历史设施；这些记录不参与调度或备降。来源中没有明确的停用前类型，因此该选项会纳入所有停用类型。
- 港口使用相同的国家、城市分区检索，也保留 UN/LOCODE。

地区展示按本项目的中国分区统一规则处理：台湾省归入中国，香港、澳门归入中国；下级标签分别为 **中国台湾省、中国香港、中国澳门**。国家列表不单独列出这三项。机场、港口、地图提示、选中字段和班次详情使用相同显示规则，原始来源代码仅用于数据关联。

分组和名称参考 [联合国统计司 M49 说明](https://unstats.un.org/unsd/methodology/m49/)：其中的 FAQ 将中国台湾省纳入中国；香港、澳门条目使用中国特别行政区名称。这里引用的是统计分区与名称说明。

## 一个可观察的连锁反应

暂停状态开始，播放或推进少量时间，让 OR101（上海浦东 → 新加坡）出发。

打开“启动一次风险演练”，注入燃油故障，然后继续推进。OR101 会根据可达设施和油量尝试备降；无法找到可达设施时进入明确的应急救援。事件面板记录：

- 原班次的故障、备降或救援。
- 共用 B-OR01 的 OR102 因载具周转推迟。
- 等待 OR101 货物的 OC902 因空海转运推迟。
- 原任务中止时，依赖它的未出发任务相应取消。

燃油或天气导致的备降 / 避港，在加油检修后继续原任务。封锁、拦阻或自定海运路线触及陆地，会尝试安全退出，并中止原任务。载具经过检修后可重新调度。

## 地图和数据

已保存 72,487 处在用航空设施：48,006 处大型 / 中型 / 小型陆地机场、23,208 处直升机起降点、1,273 处水上机场；另有 13,503 条停用设施记录供查阅。港口 3,924 个，地图 177 个地理要素，附开放海运网络。数量按来源类型分别统计，不将直升机坪算作陆地机场。

天气、洋流、冲突公告 **每 12 个真实小时检查更新**。服务每分钟检查到期时间，重启后也会检查。游戏加速不改变这个周期；手动更新有 60 秒去重间隔。

服务运行时，即使游戏网页关闭，也可以继续更新环境数据。关闭服务、电脑关机或休眠时不会继续执行；重新启动后补查。

- 全球环境采用稀疏采样，在用航线参与后续加密采样；每次最多 100 个天气采样位置，不是逐平方公里覆盖。
- 公开预报保存 72 小时时域；飞行 / 航行超出时域时会标注过期或演练外推。实际覆盖不足的路线会显示对应比例。
- 每个来源单独记录成功时间、数量和错误。某个来源失败时保留它上次成功的数据，不伪造“实时”值。
- 离线或区域缺失时使用可复现的演练环境，页面明确标注。
- 当前游戏时间从新建网络时开始。当前世界更新应用于后续模拟，不提供历史天气回放。
- 机场、港口和地图是随项目保存的目录快照，使用 **refresh-data.cmd** 手动更新，更新后重启服务。

EASA 公告是冲突风险建议，不等同于全球禁飞令。本版按国家边界近似显示，公告实际可能只覆盖某些地区、高度和运营主体。部分沿海小国在 1:110m 数据上没有单独面要素，因此无法完整绘出所有公告区域。

本版 **没有接入完整 NOTAM、国家航权、真实 ADS-B / AIS、真实班期、全球海事安全警报或付费情报库**。在“情报”中可以自定义明确标注为演练的通行限制，模拟领空封锁、外交限制或海上通道封锁。接入正式许可源应在 server/environment.mjs 新增独立适配器，而不是把演练区域改名为实时情报。

## 核心算法

- 距离：Haversine 球面距离；大圆插值；地图绘制在日期变更线处分段，避免跨屏直线。
- 海运：在开放海上航路图中，用 A* 求解；首末段连接最近的海路节点，港口出入口和狭窄运河仍是近似。
- 地速：航空巡航速度减去来风在航向上的投影；船舶航速加上洋流去向在航向上的投影，并考虑浪高减速。所有速度统一为 km/h。
- 油耗：按实际行程时间积分，天气风险和维护压力增加耗油。进场等待的飞机、港外等待的船也会消耗燃油。
- 备份燃油：飞机保留约 30–60 分钟级别的游戏备份，船舶保留 12–24 小时。低于剩余需求并进入应急阈值时检查替代设施。
- 备降 / 避港：根据当前油量、距离、设施类型兼容性、在用状态、规模、天气和区域风险寻找可达设施；沿真实位置继续移动。没有可达方案时进入有时长、费用和任务取消后果的救援抽象。
- 风险：按连续经过时间形成事件概率，使用固定种子生成可复现结果；强制演练封锁必触发通行受阻。
- 连锁延误：对载具周转和货物衔接关系传播事件，每次传播记录根事件，避免同一事件沿重复路径叠加。估计传播偏保守；实际出发还取决于前序完成和载具位置。
- 枢纽：进场 / 港口处理队列占用资源，拥堵造成等待和额外耗油。投资可以提升处理能力。
- 经济：燃油采购、租赁、维护、应急费用、收入和延误赔偿共同影响资金；故障和履约影响信誉。

飞机型号用于提供熟悉的性能层级。油耗、油箱、运载量、运行速度、风险概率、费用与维护参数均为可编辑的游戏近似，集中在 public/js/engine.js。

## 当前精度与范围

这是可玩的单人版本，支持本机服务或静态网站托管，不是专业飞行计划器或航海导航系统。低分辨率陆地检查对港口附近 70 km 作近岸近似，不模拟地形高度、跑道长度、飞机重量平衡、精确 ETOPS、船舶吃水、潮汐进港、船闸队列或船员执勤规则。海运推荐路线使用开放网络，不能保证近岸每个点的导航可行性。

本版的长期系统性来自逐步扩展的共享载具、联运依赖、枢纽排队、资金和维护；尚未提供多人、自动竞争对手、完整全球贸易需求模型或全年真实时空情景。

## 存档与运行

- data/save.json：自动保存的单个本机进度，每约 7 秒检查保存一次；右上角可手动保存。
- 多个窗口写入时使用版本号检测冲突，防止静默覆盖；冲突窗口会暂停并提示刷新。
- 页面切到后台、关闭或重新打开时，模拟暂停。不会把电脑离线时间直接算作飞行时间。
- “经营”支持导入 / 导出 JSON 存档和建立新网络；重建有明确的确认步骤。
- data/environment.json：公开世界环境缓存。
- work/server.log、work/server-error.log：运行日志。
- work/qa/：测试截图和临时测试日志。

浏览器测试需要 Playwright 和 Edge，必须连接隔离存档服务：

    # 在一个终端启动
    $env:PORT = '8788'
    node server.mjs --offline --ephemeral

    # 在另一个终端运行
    node tests/browser.mjs
    node tests/browser-search.mjs

浏览器测试会拒绝连接非 ephemeral 服务，避免覆盖正式进度。实测包括搜索、绘点、燃油警告、租赁和提交、真实触发事故、海运推荐、演练区域、在途改航、保存后重载、手机布局和页面错误检查。新增检索浏览器用例包含丹麦 → 哥本哈根 → 机场、北京、国家分页、中国地区名、直升机实际调度、停用设施只读、港口检索、手机弹层边界及正式存档哈希不变。
